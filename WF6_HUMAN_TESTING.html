2. What each tab should show

TabWhat it doesCorrect on e4.esx
Bank Every occupied slot of the 384 (256 mono + 128 stereo), with the usage meter and pool counts. 18 rows, mono 18/256 stereo 0/128, meter ≈ 2.0 / 24.0 MB. Any stereo row prints — for rate (that offset is unconfirmed).
Staging Drop WAVs; tier selector; live scoreboard. Originals are copied, never modified. Drop a .wav → one line src → staged [PACKEDNAME] N B and the meter moves. Clear empties it.
Pattern All 256 patterns, name edit, parts table, FX table, motion budget, 16-byte header as hex. 256 list rows; header line ends …offsets unproven: 40 00 03 20 …; 0/24 motion; 16 parts; 3 FX.
Motion WF5 drawable canvas. Follows the Pattern tab's selection. Selecting pattern 5 on the Pattern tab re-binds this canvas to pattern 5's slots.
Song Honest report: the song area is preserved verbatim and not decoded. "64 songs + events preserved verbatim", mid = 673,536 B, and 64 rows of raw hex at 0x130000 onward.
Global The 192-byte global block as an offset/hex/ASCII dump. 12 dump lines starting at 00000020. No MIDI-channel control anywhere — that field is undecoded.

Why three tabs show hex instead of controls

Pattern tempo/length/last-step, the song blocks, the MIDI channel, and a part's sample number all live at offsets that have never been proven — the model raises NotImplementedError for every one of them. Rendering a plausible "Tempo: 120" spinbox would be a guess the user could not distinguish from a fact, and writing a wrong byte back into a pattern is exactly the corruption this project exists to prevent. So those regions are shown as bytes until a hardware diff pins the fields. This is deliberate, not unfinished.

3. Manual test script

  1. Open a bank. File → Open… → e4.esx. Expect: title bar shows e4.esx, status bar shows the full path, all six tabs populate.
  2. Bank tab. Read the pool counts and the meter. Expect: 18 occupied rows; meter fill matches "2.0 / 24.0 MB".
  3. Pattern tab. Click pattern 005, then switch to Motion. Expect: Motion canvas now shows pattern 005's 24 slots, not pattern 000's.
  4. Rename a pattern. Pattern tab → type TESTNAME in Name → press Tab. Expect: the list row updates, the title bar gains a •, and the status bar shows modified.
  5. Stage a sample. Drag any .wav onto the Staging tab. Expect: one row appears, the scoreboard moves, and the ORIGINAL file is untouched (check its mtime).
  6. Drop a bad file. Rename a text file to fake.wav and drop it. Expect: a "Could not add" warning — not a crash. This was a real bug found and fixed in WF6.
  7. Drop a non-WAV. Drop an .aiff or .mp3. Expect: "WAV only for now" — the ffmpeg adapter is not written yet, and the app says so rather than faking a decode.
  8. Open the wizard. File → Guided setup…. Expect: an 11-page wizard. Next is never greyed out — walk from screen 1 to 11 without entering anything.
  9. Wizard ↔ Staging share one model. On wizard screen 3, add a WAV. Close the wizard. Look at the Staging tab. Expect: the same sample is there. One staging bank, two views.
  10. Wizard screen 9 writes back. Rename pattern 000 there, close the wizard. Expect: the Pattern tab list shows the new name and the window is marked modified.
  11. Wizard screen 11 — validate. Press Validate. Expect on e4.esx: 17 findings, 17 errors, all offset_past_eof. That bank has stale sample headers; it is a known-good fixture, not a bug in the app.
  12. Wizard screen 11 — refuse. Press Write bank with the override unchecked, saving to a scratch path. Expect: "Write refused: refusing to write an incoherent bank (17 error(s)…)" and no file created.
  13. Wizard screen 11 — override. Tick Write anyway, press Write bank again. Expect: "Wrote …(verified by re-read; previous kept as .bak)". Write it twice and confirm a .esx.bak appears.
  14. Round-trip proof. cmp the file you just wrote against e4.esx. Expect: byte-identical. The automated suite asserts this too, but it is worth seeing once. 
    cmp /path/to/written.esx corpus/card_backup_2026-08-22/e4.esx && echo IDENTICAL
  15. Unsaved-changes guard. Make an edit, then close the window and press Cancel. Expect: the window stays open. Press Discard and it closes.
  16. Keyboard only. Tab through a view; use Ctrl+1…Ctrl+6 to switch tabs. Expect: visible amber focus rings, every control reachable (WCAG 2.1 AA target).

Do NOT test against your real card backup as the write target

Write to a scratch path. The writer is defensive (temp file → re-read verify → atomic replace → .bak) and the round-trip gate is green on all four corpus banks, but the hardware checklist in research/HARDWARE_CHECKLIST.md is still open: no file this app wrote has yet been loaded by a real ESX-1. That is the next real-world milestone, and it is a hardware task, not a software one.

6. Two things that need your decision

a. bass_loop packs as ASS_LOOP

workspace.naming.pack_slot_name takes the last 8 characters of a basename when there is no key, because the tail usually carries the distinguishing part of a filename. On bass_loop that produces ASS_LOOP. It is the frozen TDD §5.3 rule so WF6 did not change it, but it is worth a decision: keep the tail rule, switch to a leading truncation, or add a small profanity guard.

b. Commit WF6, and start WF7?

Nothing is committed — the handoff said not to without your say-so. The branch feat/wf6-views-wizard currently holds WF6 entirely as working-tree changes. WF7 is property/golden/integration tests, CI + pre-commit hooks, README.html, NAVIGATION.md, and the _annotated companions.

7. Known limits (by design, not by omission)

  • Songs, global fields, part sample numbers, pattern tempo/length/last-step: undecoded, shown as bytes.
  • Bank.commit_sample raises NotImplementedError — staged samples are costed and named but not yet written into slots.
  • WAV only. The ffmpeg converter and librosa key detector are later adapters; the ports are already frozen so swapping them in touches no caller.
  • Motion preview is silent (visual only) — the FX renderer is phase 2.
  • Pitch is not offered as a drawable motion target; its encoding is still OPEN.
  • ui/widgets/placeholder.py is now unused. Left in place; deleting it is a WF7 call.
