01Overview, goals, non-goals

Build banks on a computer that the ESX-1 loads from card — with the sample preparation, memory budgeting, and motion authoring that the hardware's two-line display makes impractical.

Goals

#GoalSuccess looks like
G1Read and write .esx banks without ever corrupting oneByte-identical round-trip across a corpus; writes verified by re-reading before replacing anything
G2Prepare samples automaticallyDrop any format in; it is converted, key-analysed, renamed, and slotted with no manual steps
G3Make the 25 MB budget legibleA live scoreboard showing what any configuration costs, computed without re-encoding
G4Draw motion sequencesA 128-step envelope canvas per slot, honouring each target's real value domain and playback mode
G5Edit everything else in the filePatterns, parts, songs, global settings — the app is the authority on the whole bank
G6Guide a first-time userA wizard that walks every setting with the reasoning stated

Non-goals for v1

  • ES-1 / EMX-1 support. Different formats; roughly doubles codec work. Revisit after v1.
  • Real-time audio engine. Motion preview is offline render only (see §08).
  • MIDI / SysEx communication with the hardware. Card-based workflow only.
  • Bit-exact effect emulation. Explicitly out of reach; previews are approximations, labelled as such.
  • Multi-user, networking, cloud. Local, offline, single user.

02Format specification

A .esx bank is a fixed-layout image, not a container format. Regions live at absolute offsets; nothing is length-prefixed or tagged. All multi-byte integers are big-endian.

2.3 Sample header VERIFIED

MONO (40 bytes)                      STEREO (44 bytes)

  8..11  offsetChannel1Start           8..11  offsetChannel1Start

 35      (unknown)                    40..41  sampleTune

Empty slot sentinel: offset fields = 0xFFFFFFFF.

Offsets are byte offsets relative to ADDR_SAMPLE_DATA, not frame counts. Proven: reading them as frames overshoots the PCM region by 2× on every bank tested.

Allocation rule VERIFIED

Measured across 200 factory + 79 user samples: every length even, every start offset 4-byte aligned (279/279), gaps always exactly 2 or 4 bytes. One rule explains all three:

next_start = align_up(previous_end + 2, 4)
cost(sample) = align_up(frames × 2 × channels + 2, 4)
currentOffset = highest_end + 2

Sample tune encoding VERIFIED

bit 15    : sign
bits 8..14: whole semitones (0..127)
bits 0..7 : hundredths (0..99)

value = 12 × log₂(rate / 44100) + musical_offset      # SEMITONES, not cents

Confirmed against factory data: the minimum tune observed at each stored rate equals the predicted compensation to the hundredth (24 000 Hz → all six samples exactly −10.53). The field carries two concerns at once, which §05 addresses.

2.4 What the hardware accepts on import DOCUMENTED VERIFIED

PropertyAcceptedEvidence
ContainerWAV (import + export), AIFF (import only)Manual p.88
Bit depth8 or 16-bit; 8-bit is zero-expanded to 16-bit on importManual p.88
Sample rate11 025 – 96 000 Hz, a range not a listFactory bank ships 8 distinct rates: 22050, 23810, 24000, 31250, 32000, 33000, 44100, 48000

The hardware does NOT require 44.1 kHz / 16-bit

It accepts off-rate material and compensates pitch via Sample Tune. Korg's own factory content includes 48 kHz samples. Any design that presents 44.1 kHz as a hardware requirement is wrong. Pre-conversion is still the right default — for memory, for keeping Tune at 0.00, and for better offline resampling — but it is an optimisation, and the UI must say so.

2.5 Two save types DOCUMENTED

Manual p.85: Save All writes patterns + songs + global + samples. Save PSG writes pattern/song/global only, producing a shorter file with no sample area. The reader must detect and handle both; a naive minimum-size check rejects valid PSG files.

03Domain model

Pure Python objects with no I/O. Everything here is unit-testable without touching a file. Per the encapsulation standard, fields are private with behaviour exposed through methods; collections are returned as immutable views.

3.1 Class map

Bank

 ├── Pattern × 256
 │    ├── PatternHeader   (name, tempo, length, beat, lastStep, swing, roll)
 │    ├── Part × 16       (Drum×9, Keyboard×2, StretchSlice×3, AudioIn, Accent)
 │    │    └── SequenceData  (note/gate arrays, 128 steps)
 │    ├── FxUnit × 3      (type, edit1, edit2, motionSW)
 │    └── MotionSlot × 24 (target + 128 steps)
 ├── Song × 64
 │    └── SongEvent × n   (max 20 000 total)
 ├── SampleSlot × 384     (256 mono + 128 stereo)
 └── RawRegions           (the five unknown regions + anything undecoded)

3.3 Representative interface

class MotionSlot:
    """One motion sequence: a target parameter + one value per step."""

    __slots__ = ("_target", "_values")

    DISABLED = 0x80          # per-step "do not update" sentinel
    EMPTY_TARGET = 0xFFFF    # slot is unused

    def __init__(self, target: int, values: bytes):
        if len(values) != 128:
            raise ValueError(f"motion needs exactly 128 values, got {len(values)}")
        self._target = target
        self._values = bytearray(values)

    @property
    def target(self) -> int:
        return self._target

    @property
    def values(self) -> bytes:
        return bytes(self._values)        # defensive copy -- callers cannot mutate

    @property
    def in_use(self) -> bool:
        return self._target != self.EMPTY_TARGET

    def set_step(self, step: int, value: int | None, domain: "MotionDomain") -> None:
        """Set one step. `value=None` means Disabl.

        The domain snaps discrete targets to legal knob positions, so a caller
        cannot write 1 into a Filter Type field that only accepts 0/32/64/96.
        """
        self._values[step] = self.DISABLED if value is None else domain.encode(value)

    def clear(self) -> None:
        self._target = self.EMPTY_TARGET
        self._values = bytearray([self.DISABLED] * 128)

04Codec design

4.1 The governing principle

Anything not decoded is preserved verbatim

Not just the five documented unknown regions — any field the implementation has not yet decoded is stored as raw bytes and written back untouched. This is what makes byte-identical round-tripping achievable before the format is fully understood, and it is why partial decoding is safe to ship.

4.2 Read / write contract

bytes ──reader──► Bank ──writer──► bytes

CONTRACT: writer(reader(b)) == b   for every valid bank, byte for byte.

VERIFIED This gate already passes on three real banks: 4 974 396 B (79 mono samples), 20 721 848 B (200 samples, 297 motion slots), 22 960 884 B (233 samples).

4.3 "New bank" loads a template, never zeroes

Five regions are undecoded. Synthesising a bank from zeros risks a file the hardware rejects or silently misreads. New = load an embedded blank template and edit it, so unknown bytes always originate from a bank the hardware itself wrote.

4.4 Validation is a separate layer from parsing

Round-tripping does not mean the file is coherent

One of the test banks round-trips perfectly yet has 80 of 233 sample headers pointing outside the file — offsets up to 57 498 852 in a 22 960 884-byte file, exceeding even the hardware's maximum sample memory. A bank can be self-contradictory and still pass the byte-identity gate.

So validate() is separate from read() and checks the claims a file makes about itself:

  • header sample counts vs. occupied slots
  • every sample's start/end inside the PCM region, and end ≥ start
  • currentOffset ≥ highest sample end
  • sample rates within 11 025 – 96 000 Hz
  • motion targets within the known operation table

Findings are reported, never auto-repaired. Repair is an explicit user action with a preview of what would change.

4.5 Write-side safety MANDATORY

  1. Never write in place. Serialize to a temp file in the destination directory.
  2. Verify by re-reading. Parse the temp file and compare the model against what was intended.
  3. Atomic replace only after verification passes (os.replace).
  4. Keep the previous version as name.esx.bak until the user confirms the bank loads.
  5. Refuse to write a bank that fails validate() unless the user explicitly overrides.

4.6 Module layout

codec/
  layout.py          # every offset, size, count -- single source of truth
  byte_buffer.py     # big-endian cursor over bytes
  reader.py          # bytes  -> Bank      (preserves undecoded regions)
  writer.py          # Bank   -> bytes     (replays them verbatim)
  validator.py       # coherence checks, independent of parsing
  operation_table.py # 313 motion targets + value domains
  template.py        # embedded blank bank; "New" loads this

5.2 Conversion rules

StepRule
DecodeAny format ffmpeg reads. Originals are never modified.
ResampleTo the sample's chosen tier (default 44 100 Hz), with proper low-pass anti-aliasing. Naive decimation would alias and make the quality feature sound broken.
Bit depthAlways 16-bit. Dither on reduction from 24/32-bit.
ChannelsDefault mono. Stereo is a deliberate choice — it costs 2× the bytes and one of only 128 stereo slots.
smpl chunkStrip inherited chunks. The hardware overwrites the sample's End with the chunk's Loop End, so a stray smpl silently redefines where the sample ends. Loop points are written deliberately from the staging UI or not at all.

5.3 Key detection and naming

Camelot and classical notation are a bijection, so one is always derived from the other and they cannot disagree.

Slot-name convention

  [a|b]  [NN]   [classical]   [tail of basename, uppercased]
    │      │          │              └─ as many chars as still fit, taken from the END
    │      │          └─ classical key, short form (C, Am, F#m)
    │      └─ Camelot number, zero-padded to 2
    └─ Camelot letter FIRST (a = minor, b = major)
  total = 8 bytes, hard limit
CamelotLong formShort form (default)Camelot only
8B — C majorb08CmajM · 1 charb08CDRUM · 4b08KDRUM · 5
8A — A minora08AminM · 1 chara08AmRUM · 3a08KDRUM · 5
12A — C♯ minora12C#min · 0a12C#mUM · 2a12KDRUM · 5

Long-form classical leaves at most one character of the name and nothing for any sharp or flat key — 10 of the 24 Camelot positions. Short form is therefore the default. Taking the name from the tail is deliberate: trailing characters distinguish numbered variants (kick01 / kick02).

Two namespaces

The staging filename on disk carries the full both-notation name (kickdrum_Am_8A.wav) — no length limit, and that is where both notations are actually useful for browsing. The 8-byte slot name carries the packed form. Live preview shows exactly what the hardware will display before commit.

5.4 Displaying tune correctly

Show musical tune, not stored tune

The Tune field mixes rate compensation with musical transposition. A 22 050 Hz sample at its natural pitch stores as −12.00 and would read as "detuned" when it is not. The UI must display:

musical_tune = stored_tune − 12 × log₂(rate / 44100)

so an untransposed sample always shows 0.00 whatever its storage rate, with the compensation shown separately as a derived, read-only value.

06Quality budget & limits

6.1 The scoreboard is exact arithmetic, not an estimate

The format stores uncompressed PCM — no codec, no variable bitrate. So cost is closed-form, and only the duration is needed, read from the file header without decoding audio.

frames = round(duration_seconds × target_rate)
cost   = align_up(frames × 2 × channels + 2, 4)

MEASURED 194 real WAVs probed in 0.38 s, no audio decoded. Uncertainty is ±1 frame of resampler rounding — ±2 bytes against 25 MB.

6.2 Three levers, and rate is the least valuable

#LeverSavingAudible cost
1Duration — trim before importUnbounded. In a real 194-file folder the top 5 files were 59% of the totalNone, if trimming to the useful part
2Channels — fold stereo to monoExactly 2×, and frees a scarce stereo slot (128 vs 256)Usually low for drums and bass
3Rate — the quality tier2× per halvingHighest — it is the bandwidth itself

Folding 96 stereo sources to mono at full CD quality frees the identical bytes as dropping every sample to 22 kHz, and for most material is far less audible. The scoreboard therefore presents rate × channels as a matrix, and the fit-assistant proposes trimming and mono-folding before degrading bandwidth.

6.3 The quality ladder

TierRateSeconds in a full bankGainTune costMax single sample
CD — default44 100285.31.00×0.00 st228.3 s
Broadcast32 000393.21.38×−5.55 st314.6 s

Bit depth is not a quality axis: the file stores 16-bit always and 8-bit input is zero-expanded, so it saves nothing while sounding worse. Bit-crushing remains available as an aesthetic effect only.

6.4 Oversize policy

A single sample may occupy up to 80% of sample memory (20 132 659 B), leaving 20% free. Long samples are a legitimate technique — assign a long recording to a part and motion-sequence its Start Point to scrub slowly through it.

LevelMeaningDismissible
BLOCKExceeds the single-sample cap, or exceeds remaining free spaceNo — ignoring it produces an unwritable bank
WARNlarge_sample, large_source, dominant_sampleYes — grouped, so one "ignore all size warnings" click covers the family
NOTICEanalysis_skippedYes

"Ignore for all" mutes a code, not an individual sample, so dismissing once silences it for every subsequent oversized sample. BLOCK is never mutable.

BLOCK messages name the fixes that would actually work rather than saying "make it smaller":

484.7s at 44100 Hz needs 42,748,780 B. One sample may use at most 80% of
sample memory (20,132,659 B), leaving 20% free.
Options: drop to Lo-fi (16000 Hz) mono; trim to 228s at CD mono.

6.5 Why analysis is skipped on long files

Not for speed — for correctness

Key analysis costs ~11 ms per second of audio; even a 485-second recording finishes in 5.5 s. Speed is not the issue. The issue is that a global key for a long multi-section recording is musically meaningless, and because the key is appended to the filename, a bogus estimate permanently mislabels the file in the user's library. Above ANALYSIS_MAX_SECONDS (default 30 s — 8 bars at 60 BPM) the sample is marked "not analysed" and no key is appended.

"Analyse the first 30 s" is offered as an explicit action, never automatic — silently analysing a fragment and presenting it as the file's key is the same mislabelling problem in a subtler form.

07Staging bank & lifecycle

7.1 Workflow

  [1] DROP        any format, any rate, any depth
        │
  [2] PROBE       duration + rate + channels from the header (no decode)
        │         -> scoreboard updates instantly
        │         -> limits.check_sample() -> BLOCK / WARN / NOTICE
  [3] CONVERT     -> chosen tier, 16-bit, mono by default
        │            copy written to the session temp dir; ORIGINAL UNTOUCHED
  [4] ANALYSE     key -> classic + Camelot   (skipped if over the length limit)
        │
  [5] RENAME      staging file gets the full  name_Am_8A.wav
        │
  [6] DISPLAY     waveform, key, duration, memory cost, tier
        │
  [7] ASSIGN      target slot; 8-char machine name via the naming policy
        │
  [8] COMMIT      PCM appended at currentOffset; header written; counts updated
        │
  [9] CLEAR       temp dir removed on close, on "Clear", or swept at next launch

7.2 Temp lifecycle must survive a crash

"Delete on close" is not sufficient

It does nothing if the process is killed. Design:

  • Session directory named esxstudio-<pid>-<timestamp>/ under the OS temp dir.
  • A lockfile inside it holding the owning PID.
  • Orphan sweep at startup: any session dir whose PID is no longer alive is removed.
  • Explicit "Clear" button removes the current session's converted copies and resets the staging bank.

Without the sweep, a tool like this quietly fills a disk with converted WAVs.

7.3 Re-encoding from source, always

Changing a sample's tier re-encodes from the original file, never from an already-downgraded copy. Tiers are therefore freely revisable with no generation loss — a user can try Telephone, dislike it, and return to CD with nothing lost.

08Motion sequencing

The centrepiece. A motion sequence is a 128-step, 8-bit envelope bound to a named target — which makes drawing one a solved UI problem rather than a research problem.

8.1 Data model VERIFIED

struct MotionSlot {          // 130 bytes, 24 per pattern, at pattern offset 1160
    uint16_be target;        // 0xFFFF = slot unused
    uint8     value[128];    // one per step; 0x80 = Disabl
}

128 steps is exactly the maximum: LastStep (1–16) × PatternLength (1–8 bars) = 128.

8.2 The three states of a step

Disabl = 128 (0x80) — proven in factory data

pattern 3, slot 0, target 102 (Drum4 Filter Cutoff):
steps  0..5     128 128 128 128 128 128          ← disabled, motion has not started
steps  6..63     35  31  33 ... 117 126 127      ← a real filter sweep
steps 64..127   128 128 128 ... 128 128 128      ← disabled: pattern is 64 steps long

The trailing block begins exactly at the pattern's length. So each step is a value, Disabl, or beyond the pattern length — three states, not two. The canvas renders Disabl as a gap, never as zero: drawing zero is musically the opposite of leaving a parameter alone.

8.3 Value domains VERIFIED

Discrete parameters store knob positions, not option indices

Writing 0,1,2,3 into a Filter Type field would produce banks that load fine and behave wrongly. The real encoding divides the 0–127 knob range into N zones:

KindNStored bytesRule
Roll, Effect Send, Amp EG, Reverse2{0, 64}i × 64
Effect Select (Fx1/Fx2/Fx3)3{0, 43, 86}i × 43
Filter Type (LPF/HPF/BPF/BPF+)4{0, 32, 64, 96}i × 32

General rule: value = i × ceil(128 / N); decode with i = value // ceil(128 / N). Observed option counts match the manual's enum lists exactly.

This also resolved a manual erratum: REVERSE shows exactly two values {0, 64} — boolean, confirming the parameter reference and confirming that p.71's "Disabl, 0...127" is a typo.

Continuous targets store 0–127 directly. Full table in research/motion_byte_encodings.md.

8.4 Playback modes drive rendering

ScopeRule
Effects (FX1–3 Edit1/Edit2)Always SMOOTH — the part setting does not apply
Accent partAlways TRIG HOLD; LEVEL is its only automatable parameter
AMP EG, ROLL, REVERSE, FX SELECT, FX SEND, MOD TYPE, MOD DEST, BPM SYNC, FILTER TYPEAlways TRIG HOLD even when SMOOTH is selected

The canvas must draw forced-TRIG targets as latched staircases regardless of the part setting, or it shows curves the hardware will never produce.

8.6 Preview — phase 2 only

Offline render to a buffer, then play. Not a real-time audio callback: that invites buffer-underrun and threading bugs, which is precisely the risk to avoid. Approximate models of the 16 FX types behind an explicit toggle, labelled "approximate" in the UI. Phase 1 ships silent.

10.2 Separation rules

  • UI never touches codec/ directly — it goes through the domain model.
  • No business logic in widgets. A widget renders state and emits intent.
  • All long operations (conversion, analysis) run on Qt worker threads with progress and cancellation; the model is only mutated on the main thread.

10.3 Theme

An ESX-1-inspired motif: dark chassis, amber backlit-LCD accents, orange step-key highlights. Defined entirely in theme.py as tokens (colours, fonts, spacing, radii) so the whole look is editable in one file. Accessibility target WCAG 2.1 AA: 4.5:1 contrast on normal text, full keyboard navigation, visible focus, usable at 200% zoom.

11Test strategy

11.1 The corpus gate

The single most important test: every bank in the corpus must round-trip byte-identically. Runs in CI on every commit. Currently 3 real banks; grows as more are collected.

11.2 Layers

11.3 Hardware-in-the-loop

Not automatable, but decisive. Procedure: change one thing on the ESX-1, save to card, diff against the previous save. The single changed byte range answers the question. This is how the remaining open items close.

12Risks & open questions

RiskSeverityMitigation
Writing a malformed bank damages a working cardHighNever write in place; verify by re-reading; keep .bak; wizard offers a card backup before first write
Undecoded regions silently corruptedHighVerbatim passthrough + the corpus round-trip gate in CI
Full-scope editing means a codec bug can destroy patterns and songs, not just samplesHigh98% coverage target on codec/; golden-file tests; validation before write
Pitch encoding still unknownMediumTreat as raw 0–255, never clamp; resolve by hardware knob sweep before exposing Pitch in the motion editor
Stereo header path untestedMediumAll three corpus banks are mono-only. Do not ship stereo import until a stereo bank is round-tripped
Key detection wrong on atonal materialMediumReturn None rather than guessing; confidence score; manual override; suppress suffix for percussion
Approximate FX preview misleadsLowPhase 2, behind a toggle, labelled approximate
24-slot motion limit frustrates mid-editLowContinuous budget display; refuse loudly, never drop silently

Open questions OPEN

  1. Pitch value mapping. Observed bands 0–115 and 167–222 with nothing between; the manual's −63…+63 does not map onto this. One hardware knob-sweep recording settles it.
  2. Stereo second channel-offset pair. Structure inferred from blank slots; no populated stereo sample has been seen.
  3. Displayable character set. Lowercase round-trips in the file, but whether the dial can enter it and the LCD render it — and whether # exists — is unconfirmed.
  4. PSG save variant. Shorter no-sample-area file; not yet obtained.
  5. Do "unknown" regions vary between identical saves? If so they are scratch, not state, and can be relaxed.
  6. Does the hardware tolerate stale sample headers? One corpus bank has 80. If it loads, repair; if not, prune.
