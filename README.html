ESX Bank Studio

Build Korg Electribe SX banks on a computer — with the sample preparation, memory budgeting, and motion authoring the hardware's two-line display makes impractical. Offline, local, and built so it cannot corrupt a bank.

What it does

Reads and writes safely

Byte-identical round-trip on every real bank tested. Writes go to a temp file, are verified by re-reading, then atomically replace — and the previous version is kept as .bak. An incoherent bank is refused unless you explicitly override.

Makes the 25 MB budget legible

A live scoreboard showing what any configuration costs, computed from headers without re-encoding anything.

Draws motion sequences

A 128-step canvas per slot that honours each target's real value domain — a 4-option target snaps to {0,32,64,96}, never to 0/1/2/3.

Guides a first-time user

An eleven-screen wizard that states the decision and the reasoning on every screen, and never blocks Next.

Tests that need a real .esx bank skip automatically — *.esx is gitignored, so a fresh clone still runs the full gate against tests/synthetic.py, a coherent bank built deterministically in memory. Set ESX_NO_CORPUS=1 to simulate that locally.

Architecture

ui/            presentation — renders state, emits intent, never touches bytes
 ├─ session.py     THE composition root: the only UI object that imports codec/
 ├─ views/         one widget per region (bank, staging, pattern, song, global)
 ├─ motion/        drawable canvas + pure tools + target picker
 ├─ wizard/        11 skippable guided-setup pages
 └─ widgets/       BudgetMeter, KnobDial, StepGrid, WaveformView

workspace/     application services — budget, limits, naming, staging lifecycle
audio/         ports (Protocols) + the WAV passthrough adapter
codec/         bytes <-> domain: reader, writer, validator, template, layout
core/          the domain model — pure Python, no I/O, no Qt

Full map with module relationships and entry points: NAVIGATION.md.

The two rules that shape everything

  • Undecoded bytes are carried verbatim. RawRegions has no setter, so "never modify unknown regions" is structural rather than a convention — and that is what makes the round-trip byte-identical.
  • An unproven field raises rather than guesses. Where a field HAS been established it is decoded and editable, and the evidence is recorded — 728/728 parts pointing at an occupied slot, 19 of 20 tempos landing on exact integer BPMs. Where it has not, the accessor raises and the UI shows bytes. A plausible wrong number the user cannot distinguish from a fact is the failure mode this project exists to prevent.

Not yet verified on hardware

No file this app has written has been loaded by a real ESX-1 yet. The round-trip gate is green on four real banks and writes are defensive, but until the checklist in research/HARDWARE_CHECKLIST.md is closed, keep a card backup. Six open items (pitch mapping, stereo headers, character set, PSG variant, unknown-region stability, stale-header tolerance) each need button presses on the device.

Contributing

  • Branch from main as feat/, fix/, docs/, refactor/. Conventional Commits.
  • pre-commit install before your first commit — it formats, lints, blocks secrets, and refuses a committed .esx.
  • Never regress the round-trip gate. If your change alters emitted bytes, the golden hash fails; say why in the findings log.
  • Do not invent a field offset. If it is not in research/ as VERIFIED or DOCUMENTED, it raises.
  • Widgets do not import codec/. Business logic does not live in a widget.
