00What changed, and why it is not just a rescale

Dropping from a ceiling of 8 to 2 does not simply make the same plan slower. It inverts which decisions matter. Five things change:

#ChangeReason
1Consolidate agents: 22 → 19, with tasks merged into larger unitsAt 2 slots, splitting work into many small agents adds startup and context-establishment overhead without buying throughput. Fewer, larger agents win.
2Queue order becomes the critical path — longest task firstAt 8 slots everything starts at once and order is irrelevant. At 2 slots, whatever starts first determines when the last thing finishes.
3Sonnet 5 is now a throughput lever, not just a cost leverWall-clock ≈ total agent-time ÷ 2. A faster agent frees its slot sooner, so the model mix directly shortens the schedule. At 8 slots this was purely economic.
4Barriers get 4× more expensive — only the gate keeps oneIdling one of two slots wastes 50% of capacity; at 8 slots it wastes 12.5%. Everything else uses pipeline().
5More, smaller workflows (7 instead of 5)Each is only 1–3 rounds at this ceiling, so finer checkpointing is free rather than costly.

The honest cost: about 1.5×, not 4×

Intuition says a 4× lower ceiling means 4× the wall-clock. It doesn't, because the plan was never able to use 8 slots — the dependency graph was the binding constraint, not available capacity. The widest genuinely-parallel wave is 5 tasks.

At a ceiling of 8 the schedule is dependency-bound at roughly 7 rounds. At 2 it is work-bound at roughly 10–11 rounds. The real penalty is ~1.5×, and the model mix claws back part of that.

The one real constraint: PySide6 is pinned to 6.9.3

Pinned deliberately in deploy/requirements-local.txt. The Qt APIs this project uses — widgets, QPainter, QGraphicsView, file dialogs — are stable across 6.9 → 6.11, so code written here runs unchanged on the M4 mini (6.11.1). The contract-freeze agent must not use any API introduced after 6.9, and CI should pin the same version so drift is caught immediately rather than at the machine boundary.

02Scheduling model

With two slots, the schedule is a pipeline, not a fan-out. pipeline() keeps both slots busy: as each task finishes, the next queued one starts immediately, with no barrier.

slot 1 ██████████ codec-io (XL, Opus) ██████████▶
slot 2 ███ op-table ▶███ audio ▶█████ validator ▶█████ core-domain ▶
       └─ short Sonnet tasks churn while the long Opus task occupies slot 1

Three ordering rules

  1. Longest first. The XL task must start in round 1 or it becomes the tail.
  2. Pair long-Opus with short-Sonnet. While a big correctness-critical task holds one slot, the other churns through cheap mechanical work.
  3. Never barrier except at the gate. One barrier is justified; it protects everything downstream from an unverified codec.

04The seven workflows

WF1 — Contract freeze 1 agent · 1 round

Opus · max. Runs alone; everything depends on it. Writes every public signature, type hint, docstring, invariant and exception across core/, codec/, audio/ports.py, workspace/, with bodies raising NotImplementedError. Must target the PySide6 6.9 API surface.

CHECKPOINT — review the frozen API before anything is built against it.

WF2 — Foundation 5 agents · ~3 rounds

Queue order matters. Longest first, Sonnet interleaved so slot 2 turns over repeatedly:

1. codec reader+writer   Opus  xhigh  XL   ← starts immediately, holds slot 1
2. operation_table       Sonnet low   S    ← quick, frees slot 2 fast
3. audio adapters        Sonnet med   M
4. codec validator+tmpl  Opus  high   M
5. core domain model     Opus  high   L

All five depend only on WF1, so they never block each other. File ownership is disjoint — no worktrees needed.

WF3 — The gate 2 agents · barrier

integrate + run the corpus gateOpus · xhigh
adversarial review — prompted to break the writerOpus · xhigh

Hard exit: byte-identical round-trip on all three banks, plus ≥98% line coverage on codec/. Nothing downstream starts otherwise.

WF4 — UI foundation 2 agents · 1 round

1. theme + shell + widgets   Opus   high  L   ← everything visual depends on this
2. workspace                 Sonnet med   M   ← independent, fills slot 2

WF5 — Motion editor 3 agents · ~2 rounds

1. motion canvas             Opus   xhigh XL  ← three-state steps, domain snapping,
